Module dependency graph

Includes both executables: procinsh (HTTP server) and procinsh_privileged_helper (privileged acquisition helper). Each executable has its own module tree, including its copy of the shared IPC modules.

Arrows mean source module → referenced module interface. Imports and explicit paths in expressions and types point to the interface named in the source: use symbol::ElfCache points to symbol, even when the type is defined in symbol::cache. Direct implementation references and re-export declarations retain their own dependencies. Unused imports also count.

The graph uses the normal-build rustc configuration recorded in the source graph JSON; test-only code and external crates are excluded. Macro expansion, attribute arguments, and dependencies known only through type inference are not analyzed. Unresolved explicit internal paths are reported in the JSON diagnostics and build log. This is a source-reference graph, not a complete semantic dependency graph.

Opposite arrows show mutual dependencies; longer cycles can be followed along the arrows.
