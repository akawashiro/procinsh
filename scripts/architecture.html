Module dependency graph

Includes both executables: procinsh (HTTP server) and procinsh_privileged_helper (privileged acquisition helper). Each executable has its own module tree, including its copy of the shared IPC modules.

Arrows mean user → dependency, projected onto module boundaries. An incoming arrow stops at the first target-side child below the modules' common ancestor. For example, snapshot::unwind → snapshot::symbol::cache becomes snapshot::unwind → snapshot::symbol. Arrows to containers end at their outline. Dependencies between children inside a module remain visible within that module; references to ancestors keep their original targets.

This projection groups both re-exported and directly referenced internals. It does not identify the interface used in the source, and can hide internal dependency cycles. The raw diagram below preserves the resolved targets for inspection.
